=============== SHA-256 X BCrypt ===============


- SHA-256 é adequado para tokens porque eles já são valores grandes e aleatórios, dificilmente adivinhados por tentativa.
  Nesse caso, o objetivo é apenas comparar o token recebido com o hash salvo.


- SHA-256 é pouco usado para senhas pois é muito rápido, permitindo que atacantes testem muitas combinações por segundo.
  Além disso, sem salt, senhas iguais geram o mesmo hash, facilitando ataques com Rainbow Tables (tabelas com valores pré salvos correspondentes a senhas).


- BCrypt é usado para senhas porque adiciona um salt aleatório junto da senha antes de gerar o hash, fazendo com que a mesma senha gere hashes diferentes.
  Além disso, é propositalmente lento (tempo que leva para gerar e verificar cada hash.),
  reduzindo a quantidade de tentativas que um atacante consegue fazer.



=============== SHA-256 ===============


Hash criptográfico usado para transformar dados em uma assinatura fixa.


Entrada:

"meu-refresh-token"

        |
        v

     SHA-256

        |
        v

"8af92bd81c92..."


Características:

→ Mesmo valor sempre gera o mesmo hash

→ Muito rápido

→ Não possui salt automático (valor aleatório adicionado ao dado antes de fazer o hash.)

→ Feito para comparação e integridade


Exemplo:

Refresh Token:

token original:
abc123xyz


Banco salva:

    SHA256(abc123xyz) = 91ac82...


Quando chega um novo refresh:

Recebe:
    abc123xyz


Faz novamente:

SHA256(abc123xyz)

Compara:

hash recebido == hash banco

Se igual:
token válido


Usado para:

→ Refresh Tokens
→ Integridade de arquivos


Não usar para senha porque é rápido demais.


=============== BCrypt ===============


Algoritmo feito especificamente para guardar senhas.


Objetivo:

Tornar cada tentativa de senha cara para impedir
ataques de força bruta.


Exemplo:

Senha:

"minhaSenha123"


        |
        v

      BCrypt


        |
        v

$2a$12$8f82hd...


Características:

    → É lento propositalmente

    → Possui salt automático

    → Cada execução gera um hash diferente


Exemplo:


    bcrypt("senha123")

    resultado:

        $2a$12$abc...


    bcrypt("senha123")

    resultado:

        $2a$12$xyz...


Mesmo sendo diferentes, BCrypt consegue validar:


      senha digitada
            |
            v
    bcrypt.matches()
            |
            v
       true / false


Porque o próprio hash guarda informações do salt e custo.


Usado para:

    → Senhas de usuários
