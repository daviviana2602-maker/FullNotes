================= Flow de criação de conta com RabbitMQ no AtlasBank =================

(Sendo considerado para explicação meu projeto AtlasBank, parte de criação de usuário. Projeto presente no GitHub.)


    1. Conta é criada e já retorna OK pro front
       (usuário não fica esperando o envio do email)

            ↓

    2. UserRegisteredEvent é criado e o Producer publica
       (CreateAccountService)

            ↓

    3. Event é convertido para uma mensagem JSON

            ↓

    4. Mensagem JSON chega no atlas.exchange

            ↓

    5. Exchange olha a Routing Key:
       "user.registered"

            ↓

    6. Binding diz:
       "user.registered" → USER_REGISTERED_QUEUE

            ↓

    7. Exchange coloca a mensagem na USER_REGISTERED_QUEUE

            ↓

    8. EmailConsumer recebe/escuta a mensagem

            ↓

    9. Mensagem JSON é convertida novamente para
       UserRegisteredEvent (objeto Java)

            ↓

    10. EmailConsumer tenta enviar o email pelo Resend

            ↓
          SUCESSO
            ↓
           ACK  (Mensagem é removida da fila)

          OU

          FALHA
            ↓
       Retry entra em ação
            ↓
       espera 7 minutos e tenta novamente 3 vezes (além da primeira vez que deu falha, totalizando 4 tentativas)
            ↓
       caso falhar em todas, mensagem é descartada, visto que foram 21 minutos e token tem duração de 30
            ↓
       usuário precisa mandar outra solicitação    



================= Test flow do RabbitMQ com uso do RabbitPanel =================


→ Abrir o RabbitMQ Management:   http://localhost:15672

→ Exchanges
→ atlas.exchange
→ Sessão Publish message


        Routing key:

                user.registered

        Payload:

                {
                "email": "seu@email.com",
                "token": "abc123"
                }


        → Publish message (publicar a mensagem)


Resultado esperado:

           atlas.exchange

                ↓ (quando atlas.exchange recebe user.registered o binding faz o exchange mandar a message para email.queue)

           email.queue

                ↓

           EmailConsumer (ouve a mensagem na email.queue)

                ↓

        EmailService (responsável por montar o email e chamar o resendClient.sendEmail)

                ↓

        Resend (dispara email)

                ↓

          email recebido


- Esse teste mostra o ciclo completo de funcionamento
- A mensagem foi publicada diretamente pelo RabbitPanel, não passando pelo CreateAccountService, então podemos verificar que não teremos o usuário no banco de dados
